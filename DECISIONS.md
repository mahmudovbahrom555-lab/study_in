# Архитектурные решения (ADR)

Документирует отклонения от ТЗ и архитектурные выборы с обоснованием.

---

## 2026-06-11 sqlx без sqlc

**Решение:** Используем только sqlx, без sqlc.

**Причина:** ТЗ упоминает `sqlx + sqlc`, но sqlc требует настройки кодогенерации и отдельного yaml-конфига. Для MVP с одной командой sqlx достаточно и быстрее в разработке. Типобезопасность достигается через тщательное именование тегов `db:""` в structs.

**Когда пересмотреть:** Если команда вырастет до 3+ бэкендеров и SQL-запросы станут сложными.

---

## 2026-06-11 SHA-256 для хэширования refresh-токенов

**Решение:** Хэшируем refresh-токены через SHA-256 (stdlib), не bcrypt.

**Причина:** Refresh-токены — случайные 32 байта (crypto/rand). SHA-256 достаточен и быстрее bcrypt в 100+ раз. bcrypt нужен для паролей (предсказуемые данные), но не для случайных токенов.

## 2026-06-11 MinIO bucket — убираем анонимный доступ

**Решение:** Убираем `mc anonymous set download` из docker-compose.yml.

**Причина:** ТЗ явно указывает "Signed URLs для файлов — TTL 1 час". Анонимный bucket публичен навсегда — противоречит концепции безопасности. Все файлы доступны только через signed URLs с TTL.

## 2026-06-11 CORS AllowedOrigins — конфигурируемый через env

**Решение:** `SERVER_ALLOWED_ORIGINS` env var, default `*` (только для разработки).

**Причина:** В продакшене CORS должен ограничивать origin. Захардкоденный `*` нельзя поменять без передеплоя. Конфигурируемость через env — минимальный cost, максимальная безопасность.

## 2026-06-11 flutter_image_compress — добавляем в Этапе 4

**Решение:** Зависимость добавляется при реализации загрузки файлов ДЗ.

**Причина:** Фото тетради с современной камеры 5-10 МБ. Сжатие до 1200px / JPEG 80% снизит размер в 5-10x. Добавляем при реализации, не заранее.

## 2026-10-03 Релиз на двух языках: русский и английский

**Решение:** Первый релиз выпускается на **двух языках — русском и английском**. Заменяет решение D6 брифа (4 локали: uz-latn, uz-cyrl, ru, en с запуском uz → ru → en). Принято владельцем.

**Открыто:** язык по умолчанию при первом запуске (предложение: по языку системы, иначе русский).

## 2026-10-03 Правило выбора языка и двуязычная SMS

**Решение (язык интерфейса при первом запуске):**
1. Язык, вручную выбранный в приложении, — всегда главнее (хранится на устройстве и в профиле `users.language`).
2. Основной язык телефона русский → русский; английский → английский.
3. Языки стран бывшего СССР (uz, kk, ky, tg, tk, az, hy, be) → русский.
4. Остальной мир (в т.ч. Филиппины) → английский.

Украинский, грузинский, литовский, латышский, эстонский → **английский**: русский по умолчанию там может восприниматься негативно. Переключатель «Русский / English» есть на экране входа.

**Решение (SMS):** пока язык пользователя до входа неизвестен, код отправляется одной SMS на двух языках — сначала английский, затем русский. Текст укладывается в 70 символов (лимит одного SMS в кодировке UCS-2), чтобы не платить за второй сегмент; это проверяет тест `message_test.go`.

**Код:** `flutter_app/lib/core/localization/locale_resolver.dart`, `backend/internal/features/auth/service.go`.

## 2026-10-06 MVP без веб-версии; родитель приходит по ссылке-приглашению

**Решение:**
- MVP — только iOS и Android, одно приложение с тремя ролями. Веб-сборка Flutter используется только для локального тестирования.
- Ученик (из аккаунта) и репетитор (из списка учеников) отправляют родителю **ссылку** через системное меню «Поделиться». Код привязки находится внутри ссылки — родитель его не вводит.
- Ссылка ведёт в App Store / Play Market; после установки и входа роль «Родитель» ставится автоматически, открывается родительский кабинет с привязанным ребёнком.
- Передача кода через установку: Android — Play Install Referrer; iOS — копирование ссылки в буфер на странице-переадресации и чтение при первом запуске; если приложение установлено — Universal Links / App Links. Ручной ввод кода — запасной путь.

**Причина:** владелец не хочет делать веб-версию в MVP; родителю нужен вход без поиска кода.

**Зависимости:** G1 (Android/iOS-проекты, публикация в сторах), собственный домен со страницей-переадресацией и файлами `assetlinks.json` / `apple-app-site-association`.

## 2026-10-07 G10: сдача ДЗ файлами; единый модуль файлов, готовый для AI

**Решение:**
- Ученик сдаёт ДЗ с вложениями: фото JPG/PNG (HEIC с iPhone приложение конвертирует в JPG), PDF, Word (`.docx`, `.doc`). До **5 файлов**, до **10 МБ** каждый. Фото сжимаются на телефоне (~1600 px).
- Тип файла определяется **по содержимому** (сигнатура), а не по расширению.
- Сдача атомарная: сначала файлы (`POST /files`), затем «сдать» со списком `file_ids`. **Пересдача разрешена, пока работа не оценена.**
- Все файлы хранятся в **едином модуле `files`** (одна таблица, метаданные: тип, размер, sha256, размеры фото); разделы ссылаются на `file_id`. `submission_attachments` переносится в него и удаляется.
- **Готовность к AI:** AI-проверка ДЗ — v3+ (бриф), сейчас только точки подключения: доступ к содержимому файла по ID через внутренний интерфейс, хэш для дедупликации. Событие «работа сдана» и производные файлы (превью, OCR) добавляются вместе с первым потребителем — без кода, который никто не вызывает.
- **Согласие на AI-обработку** спрашивается перед первым использованием AI-функции (не при регистрации) и записывается в `consent_events`.

**Причина:** без файлов не замкнут основной цикл MVP (G10); файлы — данные детей, поэтому AI только с явным согласием.

## 2026-10-10 G10 этапы 2–3: сдача и проверка ДЗ в приложении

**Решение:**
- **Ученик:** экран сдачи — комментарий, до 5 вложений (камера, галерея, PDF/Word). Файлы грузятся сразу после выбора, с прогрессом и повтором; «Сдать» отправляет только ID. Пересдача — пока работа не оценена, после оценки экран только для просмотра (оценка и комментарий учителя).
- **Сжатие фото — средствами `image_picker`** (длинная сторона ≤1600 px, JPEG ~80%, HEIC → JPEG). Отдельный `flutter_image_compress` не нужен.
- **Репетитор:** список работ по заданию — сначала непроверенные; фото — миниатюры и полноэкранный просмотр с увеличением; оценка 0–100 и комментарий прямо в карточке, оценку можно изменить.
- **PDF и Word открываются во внешнем просмотрщике телефона** (браузер/системное приложение), а не встроенным вьюером: встроенный PDF-вьюер — тяжёлая нативная зависимость, а Word внутри приложения всё равно не показать. Подписанная ссылка передаёт исходное имя файла (`Content-Disposition`), поэтому файл сохраняется как `reshenie.pdf`, а не под ключом хранилища.
- **Список заданий** сразу отвечает на «что важно»: ученику — сдано / оценка / просрочено, репетитору — «Сдали N · Проверить M». Считается двумя запросами на всю страницу, без запроса на каждое задание.

**Причина:** замыкает основной цикл MVP «задал → сдал → проверил» (G10, G7) без лишних зависимостей.

## 2026-10-14 Посещаемость в один тап

**Решение:**
- Экран занятия показывает **всех учеников группы** на выбранный день (по умолчанию сегодня, стрелки ‹ › и календарь; будущие дни закрыты). Ручной ввод ID ученика удалён.
- У ученика 4 кнопки статуса: присутствовал / отсутствовал / опоздал / уважительная причина. **Тап сохраняет сразу**, повторный тап по тому же статусу снимает отметку. Статус всегда продублирован текстом под именем — не только цветом и значком.
- Кнопка **«Остальные присутствуют»** отмечает всех неотмеченных одним запросом (`POST /groups/{id}/attendance/batch`, одна транзакция: сохраняется всё или ничего). Чужие уже поставленные отметки не трогает.
- Экран меняется сразу, при ошибке сети отметка откатывается и показывается сообщение. Пока отметка ученика сохраняется, его кнопки заблокированы.
- `GET /groups/{id}/attendance?date=` теперь отдаёт список занятия: нынешние ученики плюс вышедшие, у которых есть отметка в этот день.

**Причина:** посещаемость — ежедневное действие репетитора (JTBD «порядок вместо Telegram»); ввод ID делал его непригодным.

## 2026-10-15 Решения после аудита перед продом

**Решение:**
- **Тесты скрываются в MVP.** Ручной редактор вопросов не делаем. После MVP тесты создаются автоматически: репетитор загружает файл или вставляет текст с материалом, и ИИ составляет тест; либо репетитор вставляет готовый тест текстом, и ИИ/ML сам превращает его в интерактивный тест для учеников. Код и API тестов остаются, скрывается только вход в раздел.
- **Оценки объединяются:** оценки за ДЗ попадают в общий журнал. В данных сохраняется тип оценки (домашняя / классная / ручная), чтобы позже разделить журнал на вкладки без миграции.
- **Демо убирается** («Посмотреть демо» и создание демо-группы).

**Причина:** аудит (docs/AUDIT-2026-10-15.md) показал, что тесты без редактора бесполезны, а ручной ввод вопросов репетиторы делать не будут; два журнала оценок путают; демо создаёт мусор в аккаунте и ведёт в замороженный ИИ.

## 2026-10-16 Архитектура расширения: app-config, языки, вкладки

**Решение:**
- **`GET /api/v1/app-config`** (публичный): минимальная версия приложения (`APP_MIN_VERSION`) и включённые фичи (`APP_FEATURES`). Приложение читает его на заставке и кэширует. Версия ниже минимальной ведёт на экран «Нужно обновить приложение» со ссылкой в Google Play.
- **Флаги фич вместо скрытия кодом.** Тесты теперь скрыты флагом `quizzes` (выключен по умолчанию), а не удалённой плиткой. Новые фичи (геолокация, чат) выкатываются так же — выключенными.
- **Языки — один список с каждой стороны:** `appLanguages` во Flutter, `domain.SupportedLanguages` на сервере. Ограничение языка в БД снято (миграция 000021). Переключатель языка — меню на любое число языков. Язык профиля синхронизируется с языком интерфейса из одного места (после входа и при каждой смене), а не только при входе.
- **Вкладки главного экрана — декларативный список** с ролями (`_tabs` в `home_shell.dart`).
- **API v1 меняется только добавлением;** ломающее — через новую версию приложения и подъём `APP_MIN_VERSION`. Правила и рецепты — docs/architecture.md, раздел «Расширение без переписывания».
- **Исправлено при проверке:** родитель открывал «Оценки» и «Посещаемость» ребёнка через экраны ученика и получал «Нет доступа». Теперь экраны истории (`GradeHistoryView`, `AttendanceHistoryView`) получают данные снаружи: ученик — свои, родитель — через `/parent/children/...`. Неиспользуемые маршруты `/groups/:id/students/:id/grades|attendance` удалены.
- Геолокация, чат и события между модулями **не реализуются** — в docs/architecture.md описано, куда они встают.

**Причина:** после публикации старые версии из стора живут месяцами. Без минимальной версии любое ломающее изменение API ломает пользователей, а без флагов фичу нельзя включить без релиза. Новые языки и вкладки должны добавляться строкой, а не правкой экранов.

## 2026-10-16 Готовность к переносу данных в Узбекистан

**Решение:**
- Прод пока размещается **вне Узбекистана**. Перенос данных на сервер в Узбекистане — когда продукт вырастет. Это требование закона «О персональных данных», ст. 27-1; точные требования уточнить у юриста.
- Код к переносу готов и должен оставаться готовым:
  - постоянные данные только в Postgres и S3;
  - файлы хранятся по ключу, а не по ссылке;
  - приложение обращается к домену, а не к IP;
  - вся конфигурация в переменных окружения;
  - персональные данные не уходят в push, Sentry и ИИ.
- Правила и процедура переноса — docs/architecture.md, «Перенос данных на другой сервер». Процедура оформляется и проверяется на шаге «Сервер» вместе с бэкапами.

**Причина:** переезд должен быть операцией (бэкап → восстановление → DNS), а не переписыванием кода. Домен покупается до выхода в прод: без него переезд потребует обновления приложения у всех пользователей.

## 2026-10-16 Оценки: единый журнал

**Решение:**
- **Единый журнал.** Оценка за ДЗ при проверке работы в той же транзакции записывается в `grades` (`kind = homework`, `assignment_id`). Повторная проверка обновляет ту же строку. Уже поставленные оценки за ДЗ перенесены миграцией 000022. Оценки за удалённые задания журнал не показывает.
- **Типы:** `class` — репетитор ставит в журнале, `homework` — за ДЗ. Отдельный тип «ручная» не вводили: в журнале репетитор ставит только оценку за работу на занятии, это и есть `class`. Новые типы добавляются расширением CHECK в миграции.
- **Оценку за ДЗ в журнале нельзя изменить или удалить** (`HOMEWORK_GRADE_READONLY`): она меняется только при проверке работы, иначе журнал и работа разойдутся.
- **Форма оценки:**
  - ученик выбирается из списка группы;
  - поле «За что» вместо «Предмет»;
  - балл с запятой или точкой; 0 допустим, больше максимума нельзя (проверяют и приложение, и сервер);
  - при ошибке форма не закрывается и показывает причину;
  - «За что» и максимум запоминаются до перезапуска приложения, чтобы оценить всю группу подряд.
- **В журнале:**
  - имя ученика и метка «ДЗ»;
  - баллы без лишних нулей и с разделителем языка («4,5», «90 / 100»);
  - удаление с подтверждением.
- **Исправлено:**
  - приложение удаляло оценку по несуществующему адресу (`/grades/{id}`);
  - кружок с оценкой округлял 4,5 до «5»;
  - неиспользуемый `updateGrade` во Flutter удалён.

**Причина:** аудит 2026-10-15: оценки ставились вводом ID, ошибки не показывались, 0 не принимался, два журнала путали.

- **Удаление аккаунта — сразу и полностью**, без «корзины» на 30 дней: так проще выполнить требование Google Play и политику.
  - В приложении: «Аккаунт → Удалить аккаунт», подтверждение с перечнем последствий.
  - Без приложения: страница `/account/delete` на том же сервере. Вход по коду из SMS через обычные эндпоинты, затем `DELETE /me`. Эту ссылку указываем в Play Console.
- **Что удаляется:** всё, что ссылается на пользователя. Все внешние ключи на `users` теперь каскадные: миграция 000023 перевела `grades.teacher_id` и `attendance.teacher_id`, без неё аккаунт репетитора не удалялся.
  - **Репетитор:** вместе с ним удаляются его группы со всем содержимым, включая работы и файлы учеников в этих группах. Приложение предупреждает об этом с числом групп. Аккаунты учеников остаются.
  - **Ученик:** удаляются его участие, сдачи, оценки, посещаемость и связь с родителем. Группа остаётся.
- **Файлы в хранилище** удаляются после транзакции БД. Если файл не удалось стереть, удаление аккаунта не отменяется — ошибка пишется в лог.
- **Согласие с политикой:**
  - экран входа показывает «Продолжая, вы принимаете политику конфиденциальности» со ссылкой;
  - приложение отправляет при входе версию политики (`AppConfig.privacyVersion`);
  - при создании аккаунта сервер пишет в `consent_events` тип `privacy_policy`, версию, IP и устройство.
  - Ссылка на политику есть и в «Аккаунте». Адрес — `AppConfig.privacyUrl` (`mamulearn.uz/privacy`), страницу нужно опубликовать на домене.

**Причина:** без удаления аккаунта и политики Google Play не пропустит приложение, особенно с детьми среди пользователей.

## 2026-10-17 Краши, без демо, главный экран родителя

**Решение:**
- **Сбор крашей в приложении — Sentry** (`sentry_flutter` 9.30, `core/monitoring/crash_reporting.dart`).
  - Включается сборкой с `--dart-define=SENTRY_DSN=...`, без DSN выключен.
  - Без персональных данных: `sendDefaultPii` выключен, без скриншотов, без снимка интерфейса и без печатных логов. На экранах имена и оценки детей — правило переноса данных.
  - Ветка 8.x не собирается с текущим Kotlin (language version 1.6).
  - Нужен аккаунт Sentry (бесплатного тарифа хватит) и его DSN. Сервер Sentry уже поддерживает через `SENTRY_DSN` в `.env`.
- **Демо удалено целиком:**
  - кнопка «Посмотреть демо»;
  - `POST /ai/me/demo`, генератор демо-группы, подмена аналитики и рекомендаций для демо;
  - колонка `groups.is_demo` (миграция 000024, демо-группы удалены).
  - Пустой экран репетитора: «Создайте первую группу и поделитесь её кодом с учениками».
- **Родитель видит только «Дети».** Вкладка «Группы» ему не нужна: он не вступает в группы, а группы ребёнка видит в карточке ребёнка. С одной вкладкой нижняя панель не показывается. Неиспользуемый маршрут `/parent/children` удалён.

**Причина:** аудит 2026-10-15 — без крашей мы не увидим ошибки на телефонах тестировщиков; демо создавало мусор и вело в замороженный ИИ; у родителя первым был бесполезный экран групп.

## 2026-10-19 Новый вектор: классы, которые можно найти

**Решение:** продукт становится сетью классов: каталог, открытые и закрытые классы с заявками, чат в классе с автоудалением через 24 часа (меньше — по выбору репетитора, дольше — платно), режим родителя с каталогом репетиторов и центров. Мессенджером себя не называем. Ядро (ДЗ, оценки, посещаемость, оплата) остаётся. Порядок: чат в классе → каталог и заявки → маркетплейс и платные функции; этапы 1–2 до внутреннего тестирования. Подробно — docs/PRODUCT-VECTOR.md.

**Причина:** инструмент даёт пользу, но не рост; сеть классов решает ещё поиск учеников и репетиторов и даёт ученику повод открывать приложение каждый день.

## 2026-10-19 Доделки перед тестом: отчёты за флагом, имя, лента без вложений

**Решение:**

Удалены таблица `post_attachments` (миграция 000025), код на сервере и в приложении. Материалы в ленте, когда понадобятся, пойдут через модуль `files`, как у ДЗ.

**Причина:** аудит 2026-10-15, пункты про остатки ИИ и неработающую кнопку в ленте; опечатку в имени нельзя было исправить.

## 2026-10-19 Чат в классе: технический дизайн утверждён

**Решение:** docs/design/CHAT.md.
- **Сообщения:** со сроком жизни (1, 6, 12 или 24 ч; новый срок — только для новых сообщений), физически удаляются фоновой задачей.
- **Отправка и доставка:** отправка через REST, доставка через одно WebSocket-соединение и Redis pub/sub, push без содержимого.
- **Модерация репетитора:** удалить сообщение, запретить писать в классе, заблокировать, режим «пишет только репетитор».
- **Жалобы на платформу:** со снимком сообщения; разбирает только владелец продукта на `/admin/reports`. За оскорбления — запрет писать во всех чатах (`users.chat_banned`), за тяжёлое — блокировка аккаунта. Уведомление о жалобе — Telegram-бот без содержимого.
- **Ссылки:** кликабельны только в сообщениях владельца класса.

**Причина:** этап 1 вектора (docs/PRODUCT-VECTOR.md): проверить на тесте, общаются ли ученики в классе.
