# Архитектурные решения (ADR)

Документирует отклонения от ТЗ и архитектурные выборы с обоснованием.

---

## 2026-06-11 sqlx без sqlc

**Решение:** Используем только sqlx, без sqlc.

**Причина:** ТЗ упоминает `sqlx + sqlc`, но sqlc требует настройки кодогенерации и отдельного yaml-конфига. Для MVP с одной командой sqlx достаточно и быстрее в разработке. Типобезопасность достигается через тщательное именование тегов `db:""` в structs.

**Когда пересмотреть:** Если команда вырастет до 3+ бэкендеров и SQL-запросы станут сложными.

---

## 2026-06-11 SHA-256 для хэширования refresh-токенов

**Решение:** Хэшируем refresh-токены через SHA-256 (stdlib), не bcrypt.

**Причина:** Refresh-токены — случайные 32 байта (crypto/rand). SHA-256 достаточен и быстрее bcrypt в 100+ раз. bcrypt нужен для паролей (предсказуемые данные), но не для случайных токенов.

## 2026-06-11 Avatar upload в Этапе 4

**Решение:** `POST /me/avatar` в Этапе 1 возвращает 501 Not Implemented.

**Причина:** Загрузка аватара требует MinIO SDK (не в go.mod). MinIO-интеграция запланирована на Этап 4 (файлы ДЗ). Добавление minio-go сейчас ради одного endpoint нецелесообразно.

## 2026-06-11 payment_status в group_members — Этап 2

**Решение:** При создании таблицы group_members в Этапе 2 добавляем поле `payment_status VARCHAR(20) DEFAULT 'pending'`.

**Причина:** Финансовый учёт — killer feature для репетиторов (согласно анализу). Добавление одного поля при создании таблицы стоит ноль усилий, но даёт огромную ценность.

## 2026-06-11 MinIO bucket — убираем анонимный доступ

**Решение:** Убираем `mc anonymous set download` из docker-compose.yml.

**Причина:** ТЗ явно указывает "Signed URLs для файлов — TTL 1 час". Анонимный bucket публичен навсегда — противоречит концепции безопасности. Все файлы доступны только через signed URLs с TTL.

---

## 2026-06-11 CORS AllowedOrigins — конфигурируемый через env

**Решение:** `SERVER_ALLOWED_ORIGINS` env var, default `*` (только для разработки).

**Причина:** В продакшене CORS должен ограничивать origin. Захардкоденный `*` нельзя поменять без передеплоя. Конфигурируемость через env — минимальный cost, максимальная безопасность.

## 2026-06-11 flutter_image_compress — добавляем в Этапе 4

**Решение:** Зависимость добавляется при реализации загрузки файлов ДЗ.

**Причина:** Фото тетради с современной камеры 5-10 МБ. Сжатие до 1200px / JPEG 80% снизит размер в 5-10x. Добавляем при реализации, не заранее.

## 2026-06-11 Verification code — не удаляем старые, берём последний

**Решение:** `GetLatestVerificationCode` получает самый свежий код по телефону.

**Причина:** Старые коды истекают через 10 минут. Простота важнее идеальной чистоты. Cleanup старых записей — cron job в Этапе 9.

## 2026-10-03 Релиз на двух языках: русский и английский

**Решение:** Первый релиз выпускается на **двух языках — русском и английском**. Заменяет решение D6 брифа (4 локали: uz-latn, uz-cyrl, ru, en с запуском uz → ru → en). Принято владельцем.

**Следствия:** узбекские локали (uz, uz-Cyrl) откладываются; их ARB-файлы не удаляем — они понадобятся позже. Все экраны переводятся на `AppLocalizations` с двумя языками; новые строки добавляются сразу в `intl_ru.arb` и `intl_en.arb`.

**Открыто:** язык по умолчанию при первом запуске (предложение: по языку системы, иначе русский).

## 2026-10-03 Правило выбора языка и двуязычная SMS

**Решение (язык интерфейса при первом запуске):**
1. Язык, вручную выбранный в приложении, — всегда главнее (хранится на устройстве и в профиле `users.language`).
2. Основной язык телефона русский → русский; английский → английский.
3. Языки стран бывшего СССР (uz, kk, ky, tg, tk, az, hy, be) → русский.
4. Остальной мир (в т.ч. Филиппины) → английский.

Украинский, грузинский, литовский, латышский, эстонский → **английский**: русский по умолчанию там может восприниматься негативно. Переключатель «Русский / English» есть на экране входа.

**Решение (SMS):** пока язык пользователя до входа неизвестен, код отправляется одной SMS на двух языках — сначала английский, затем русский. Текст укладывается в 70 символов (лимит одного SMS в кодировке UCS-2), чтобы не платить за второй сегмент; это проверяет тест `message_test.go`.

**Код:** `flutter_app/lib/core/localization/locale_resolver.dart`, `backend/internal/features/auth/service.go`.

## 2026-10-06 MVP без веб-версии; родитель приходит по ссылке-приглашению

**Решение:**
- MVP — только iOS и Android, одно приложение с тремя ролями. Веб-сборка Flutter используется только для локального тестирования.
- Ученик (из аккаунта) и репетитор (из списка учеников) отправляют родителю **ссылку** через системное меню «Поделиться». Код привязки находится внутри ссылки — родитель его не вводит.
- Ссылка ведёт в App Store / Play Market; после установки и входа роль «Родитель» ставится автоматически, открывается родительский кабинет с привязанным ребёнком.
- Передача кода через установку: Android — Play Install Referrer; iOS — копирование ссылки в буфер на странице-переадресации и чтение при первом запуске; если приложение установлено — Universal Links / App Links. Ручной ввод кода — запасной путь.

**Причина:** владелец не хочет делать веб-версию в MVP; родителю нужен вход без поиска кода.

**Зависимости:** G1 (Android/iOS-проекты, публикация в сторах), собственный домен со страницей-переадресацией и файлами `assetlinks.json` / `apple-app-site-association`.

## 2026-10-07 G10: сдача ДЗ файлами; единый модуль файлов, готовый для AI

**Решение:**
- Ученик сдаёт ДЗ с вложениями: фото JPG/PNG (HEIC с iPhone приложение конвертирует в JPG), PDF, Word (`.docx`, `.doc`). До **5 файлов**, до **10 МБ** каждый. Фото сжимаются на телефоне (~1600 px).
- Тип файла определяется **по содержимому** (сигнатура), а не по расширению.
- Сдача атомарная: сначала файлы (`POST /files`), затем «сдать» со списком `file_ids`. **Пересдача разрешена, пока работа не оценена.**
- Все файлы хранятся в **едином модуле `files`** (одна таблица, метаданные: тип, размер, sha256, размеры фото); разделы ссылаются на `file_id`. `submission_attachments` переносится в него и удаляется.
- **Готовность к AI:** AI-проверка ДЗ — v3+ (бриф), сейчас только точки подключения: доступ к содержимому файла по ID через внутренний интерфейс, хэш для дедупликации. Событие «работа сдана» и производные файлы (превью, OCR) добавляются вместе с первым потребителем — без кода, который никто не вызывает.
- **Согласие на AI-обработку** спрашивается перед первым использованием AI-функции (не при регистрации) и записывается в `consent_events`.

**Причина:** без файлов не замкнут основной цикл MVP (G10); файлы — данные детей, поэтому AI только с явным согласием.
