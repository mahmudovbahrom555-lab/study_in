1# Технический дизайн: чат в классе (этап 1)

> Статус: **утверждено владельцем 2026-10-19** (ответы — раздел 14). Продуктовые решения — docs/PRODUCT-VECTOR.md, раздел 5. Здесь — как это устроено.

## 1. Что входит в этап 1

**Делаем:**
- текстовый чат в каждом классе: участники класса пишут, репетитор видит всё;
- автоудаление: 24 часа по умолчанию, репетитор выбирает 1, 6 или 12 часов;
- доставка сразу (WebSocket), а когда приложение закрыто — push;
- непрочитанные: число на карточке класса;
- модерация репетитором: удалить сообщение, запретить писать, удалить из класса, заблокировать, режим «пишет только репетитор»;
- жалоба на платформу на сообщение или участника; снимок сообщения хранится до разбора;
- страница разбора жалоб для владельца продукта;
- ограничение частоты сообщений;
- «Условия использования» и обновление политики конфиденциальности;
- флаг фичи `chat` — включаем сначала тестировщикам.

**Не делаем в этапе 1:** фото, голосовые, ответы на сообщение, реакции, «печатает…», «прочитано» по каждому сообщению, поиск, кликабельные ссылки у учеников, платное хранение (этап 3).

## 2. Кто что может

| Действие | Владелец класса | Участник | Участник с запретом | Родитель |
|---|---|---|---|---|
| Читать чат | да | да | да | нет (режим родителя) |
| Писать | да | да, если режим не «только репетитор» | нет | нет |
| Удалить своё сообщение | да | да | да | — |
| Удалить чужое сообщение | да | нет | нет | — |
| Запретить писать / разрешить | да | нет | нет | — |
| Заблокировать участника | да | нет | нет | — |
| Срок хранения, режим чата | да | нет | нет | — |
| Пожаловаться на платформу | да | да | да | — |

В этапе 1 участники класса — его ученики (как сегодня). Репетиторы-участники появятся в этапе 2 вместе с обобщением участников.

## 3. Данные (миграция)

### 3.1. Сообщения

```sql
CREATE TABLE chat_messages (
    id          UUID PRIMARY KEY,
    group_id    UUID NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
    author_id   UUID NOT NULL REFERENCES users(id)  ON DELETE CASCADE,
    body        TEXT NOT NULL CHECK (char_length(body) BETWEEN 1 AND 2000),
    client_id   UUID NOT NULL,            -- id от приложения: повтор отправки не создаёт дубль
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at  TIMESTAMPTZ NOT NULL,     -- created_at + срок хранения класса
    UNIQUE (author_id, client_id)
);
CREATE INDEX idx_chat_group_time ON chat_messages(group_id, created_at DESC);
CREATE INDEX idx_chat_expires    ON chat_messages(expires_at);
```

- Удаление (по таймеру, автором или репетитором) — **физическое**: сообщения детей не копятся «мягко удалёнными».
- Внешние ключи каскадные — удаление аккаунта убирает и сообщения (правило из docs/architecture.md).

### 3.2. Настройки класса и участников

```sql
ALTER TABLE groups
    ADD COLUMN chat_ttl_seconds INT NOT NULL DEFAULT 86400
        CHECK (chat_ttl_seconds IN (3600, 21600, 43200, 86400)),
    ADD COLUMN chat_mode VARCHAR(16) NOT NULL DEFAULT 'open'
        CHECK (chat_mode IN ('open', 'owner_only'));

ALTER TABLE group_members ADD COLUMN chat_muted BOOLEAN NOT NULL DEFAULT FALSE;  -- запрет в классе (репетитор)
ALTER TABLE users ADD COLUMN chat_banned BOOLEAN NOT NULL DEFAULT FALSE;         -- запрет во всех чатах (по жалобе)

CREATE TABLE group_bans (
    group_id   UUID NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
    user_id    UUID NOT NULL REFERENCES users(id)  ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (group_id, user_id)
);

CREATE TABLE chat_reads (
    group_id     UUID NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
    user_id      UUID NOT NULL REFERENCES users(id)  ON DELETE CASCADE,
    last_read_at TIMESTAMPTZ NOT NULL,
    PRIMARY KEY (group_id, user_id)
);
```

- Новый срок хранения действует на **новые** сообщения; уже отправленные живут по старому сроку. (Сокращать уже отправленные можно, но это неожиданно для участников — обсудить, если нужно.)
- Заблокированный не может вступить снова ни по коду, ни (в этапе 2) через каталог.
- Длинные сроки (7, 30 дней, без удаления) добавятся в этапе 3 расширением CHECK.

### 3.3. Жалобы

```sql
CREATE TABLE reports (
    id               UUID PRIMARY KEY,
    reporter_id      UUID REFERENCES users(id) ON DELETE SET NULL,
    group_id         UUID REFERENCES groups(id) ON DELETE SET NULL,
    target_type      VARCHAR(16) NOT NULL CHECK (target_type IN ('message', 'user')),
    target_user_id   UUID,                -- без внешнего ключа: снимок переживает удаление аккаунта
    message_id       UUID,                -- без внешнего ключа: сообщение может истечь
    message_body     TEXT,                -- снимок текста на момент жалобы
    message_sent_at  TIMESTAMPTZ,
    reason           VARCHAR(32) NOT NULL CHECK (reason IN ('spam', 'abuse', 'sexual', 'violence', 'other')),
    comment          TEXT CHECK (char_length(comment) <= 1000),
    status           VARCHAR(16) NOT NULL DEFAULT 'open' CHECK (status IN ('open', 'resolved', 'dismissed')),
    resolution       VARCHAR(32),         -- message_deleted | chat_banned | user_blocked | none
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    resolved_at      TIMESTAMPTZ
);
CREATE INDEX idx_reports_open ON reports(created_at) WHERE status = 'open';
```

- Снимок сообщения — **причина**, по которой жалоба работает несмотря на автоудаление.
- Разобранные жалобы хранятся **180 дней**, потом удаляются фоновой задачей (срок вписать в политику; уточнить у юриста).

## 4. API

Все маршруты — внутри `/api/v1`, с проверкой токена.

| Метод и путь | Что делает |
|---|---|
| `GET /groups/{id}/chat/messages?before=<id>&limit=50` | история: последние живые сообщения, страницами назад |
| `POST /groups/{id}/chat/messages` `{body, client_id}` | отправить; повтор с тем же `client_id` возвращает то же сообщение |
| `DELETE /groups/{id}/chat/messages/{msgId}` | удалить (автор или владелец класса) |
| `POST /groups/{id}/chat/read` `{last_read_at}` | отметить прочитанным |
| `PATCH /groups/{id}/chat/settings` `{ttl_seconds, mode}` | срок хранения и режим (владелец) |
| `POST /groups/{id}/members/{userId}/mute` / `unmute` | запретить / разрешить писать (владелец) |
| `POST /groups/{id}/members/{userId}/ban` | удалить из класса и заблокировать (владелец) |
| `POST /reports` `{group_id, message_id? , user_id?, reason, comment?}` | жалоба на платформу |
| `GET /ws` | WebSocket: события в реальном времени (раздел 5) |

Число непрочитанных добавляется в ответ списка групп (`unread_count`) — одна выборка на весь список, без запроса на каждую группу.

**Отправка — через REST, не через WebSocket.** Так проверка прав, ограничение частоты и ошибки работают как везде, а сокет только доставляет события. Если сокет оборвался, сообщение всё равно отправится.

## 5. Доставка в реальном времени

```
Приложение ──POST message──► API ──INSERT──► Postgres
                              │
                              └──PUBLISH chat:group:<id>──► Redis ──► все экземпляры API
                                                                       │
Приложение ◄──────── WebSocket событие message.created ◄───────────────┘
```

- **Одно соединение на приложение** (`GET /api/v1/ws`), токен в заголовке `Authorization` — не в адресе (адреса попадают в логи).
- Сервер подписывает соединение на классы пользователя; при вступлении/удалении из класса подписка обновляется.
- **Redis pub/sub** между экземплярами сервера — с первого дня, хотя сейчас экземпляр один: потом не придётся переделывать.
- События: `message.created`, `message.deleted`, `chat.settings_changed`, `member.muted`/`member.unmuted`, `member.removed`.
- Приложение при открытии чата берёт историю через REST, дальше слушает события. После переподключения догружает пропущенное через REST (по последнему id).
- Пинг каждые 30 секунд, переподключение с нарастающей паузой.
- **Ловушка:** у API сейчас тайм-аут 60 секунд на любой запрос (middleware `Timeout` и `WriteTimeout` сервера). Маршрут `/ws` монтируется **вне** middleware тайм-аута, а перед апгрейдом соединения дедлайны снимаются — иначе сокет рвётся каждую минуту.
- Библиотеки: на сервере `github.com/coder/websocket`, в приложении `web_socket_channel`.

## 6. Push

- Когда у получателя нет открытого сокета — push через FCM.
- **Текст push без содержимого и имён:** «Новые сообщения в «English B1»» (правило переноса данных и защиты детей).
- Не чаще одного push на класс на человека раз в 5 минут, чтобы не засыпать телефон.
- **Зависимость:** нужен проект Firebase от владельца. До этого — только сокет и счётчик непрочитанных.

## 7. Автоудаление

- Чтение всегда фильтрует `expires_at > NOW()` — истёкшее не видно сразу, даже если ещё не удалено.
- Фоновая задача раз в минуту удаляет истёкшие сообщения пачками (как сегодняшняя очистка файлов в `server.RunFileCleanup`).
- Событие `message.deleted` при истечении не рассылается: приложение само скрывает сообщения с прошедшим `expires_at` (это поле приходит в каждом сообщении).
- Та же задача удаляет разобранные жалобы старше 180 дней.

## 8. Жалобы и их разбор

- В приложении: долгое нажатие на сообщение → «Пожаловаться»; на участника — в его меню. Причина из списка + комментарий.
- Жалоба сохраняет снимок сообщения (раздел 3.3). Репетитор о жалобе не узнаёт (жалоба может быть на него).
- **Разбор:** страница `/admin/reports` на сервере, вход по SMS-коду, доступ только у владельца продукта (`ADMIN_USER_IDS` — переменная окружения). Действия:
  - отклонить жалобу;
  - удалить сообщение (если ещё есть);
  - **запретить писать во всех чатах** (`users.chat_banned = true`) — основная мера за оскорбления: человек остаётся в приложении (ДЗ, оценки, посещаемость), но писать в чатах не может;
  - заблокировать пользователя на платформе (`users.is_active = false` — вход и обновление сессии уже это проверяют) — для тяжёлых случаев.
- **Уведомление владельцу о новой жалобе** — Telegram-бот, только «Новая жалоба», без текста и имён (данные не уходят в Telegram). Подключается, когда владелец даст токен бота; до этого — страница разбора ежедневно.

## 9. Защита от злоупотреблений

- Не больше 20 сообщений в минуту от человека в классе (Redis, как ограничение SMS).
- Длина сообщения до 2000 символов.
- **Ссылки кликабельны только в сообщениях владельца класса** (статьи, учебные ресурсы). У остальных — текстом: меньше фишинга детям.
- Запрет писать на платформе (`chat_banned`) и блокировка (`is_active = false`) проверяются сервисом чата при каждой отправке.

## 10. Приложение

- Плитка **«Чат»** на странице класса (за флагом `chat`), число непрочитанных на карточке класса в списке.
- Экран чата: список снизу вверх, поле ввода, под заголовком подпись «Сообщения исчезают через 24 ч».
- Отправка с мгновенным появлением; при ошибке — отметка «не отправлено, повторить».
- Долгое нажатие: «Удалить» (своё; у репетитора — любое), «Пожаловаться».
- Репетитор: в меню участника — «Запретить писать», «Заблокировать»; в настройках класса — срок хранения и режим «пишет только репетитор».
- Модуль `core/realtime`: одно соединение, переподключение, раздача событий экранам (Riverpod).

## 11. Изменения в документах

- **«Условия использования»** (новый документ): что запрещено в чате, модерация репетитором, жалобы, блокировка, ответственность.
- **Политика конфиденциальности:** чат, срок хранения сообщений, снимки при жалобах и срок их хранения, push без содержимого.
- **Data safety в Play Console:** сообщения пользователей, срок хранения.

## 12. Проверка

- Тесты сервиса: права (участник, с запретом, режим «только репетитор», чужой класс, блокировка), срок жизни, повтор `client_id`, снимок жалобы, ограничение частоты.
- Тест рассылки событий на подменённом Redis.
- На эмуляторе: два участника (репетитор и ученик) — сообщение приходит сразу; истечение (поставить 1 ч и сдвинуть время в БД); удаление репетитором; запрет писать; жалоба → страница разбора → блокировка.

Push — после появления проекта Firebase (+0,5 дня).

## 14. Ответы владельца (2026-10-19)

1. Сроки хранения 1, 6, 12, 24 часа — **да**.
2. Новый срок **не сокращает** уже отправленные сообщения — только новые.
3. За оскорбления человек **не может писать** — мера `chat_banned` при разборе жалобы (раздел 8); причины жалоб — как предложено.
4. Жалобы разбирает **только владелец продукта**; уведомление — Telegram-бот без содержимого (когда будет токен).
5. Ссылки **кликабельны для репетитора** (учебные статьи и ресурсы), у учеников — текстом.
