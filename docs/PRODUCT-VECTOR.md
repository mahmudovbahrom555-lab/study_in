# Вектор продукта MaMu Learn

> Утверждено владельцем 2026-10-19. Документ описывает, **каким становится продукт** и **в каком порядке** мы его строим. Технические детали каждого этапа (схема БД, API) уточняются в DECISIONS.md перед началом кода.

---

## 1. Позиционирование

**Было:** инструмент репетитора — журнал, ДЗ, посещаемость, родитель видит результат («порядок вместо хаоса в Telegram»).

**Стало:** **классы, которые можно найти.** Репетитор создаёт класс, его находят ученики, родители и другие репетиторы — как группы в Telegram. Внутри класса — учёба (ДЗ, оценки, посещаемость) и общение (лента и чат).

- Мы **не называем себя мессенджером**, но удобны как мессенджер: быстро, привычно, в одном месте.
- Ядро-инструмент **остаётся** и остаётся главной причиной, по которой репетитор приходит в приложение. Каталог и общение растут поверх него.

**Формула в двух словах:** найди класс — учись и общайся в нём.

### Почему так

| | Инструмент (было) | Сеть классов (стало) |
|---|---|---|
| Ценность с первого дня | да, даже для одного репетитора | ядро — да; каталог — когда наполнится |
| Зачем ученику открывать каждый день | только ДЗ | общение со сверстниками по предмету |
| Рост | одиночные репетиторы | каждый новый класс делает приложение ценнее для всех |
| Заработок | подписка за журнал (мало) | хранение чата, продвижение в каталоге, центры |

## 2. Кто пользуется и зачем

| Роль | Главная работа | Что получает |
|---|---|---|
| **Репетитор** | вести учеников без хаоса; находить новых | класс с ДЗ, оценками, посещаемостью, чатом; место в каталоге |
| **Ученик** | учиться и общаться со сверстниками по предмету | классы, speaking-клубы, единомышленники, свои оценки |
| **Родитель** | видеть результат ребёнка; найти хорошего репетитора | режим результатов детей; каталог репетиторов и центров |
| **Другой репетитор** | обмен опытом, замены, совместные классы | может найти класс и вступить в него |
| **Учебный центр** (позже) | показать себя и свои классы | профиль центра в каталоге |

## 3. Класс

Класс — это сегодняшняя «группа», расширенная.

### 3.1. Открытый и закрытый

| | Открытый | Закрытый |
|---|---|---|
| Виден в каталоге | да | да (описание и репетитор) |
| Вступление | сразу | заявка → репетитор подтверждает |
| Вход по коду приглашения | да | да, без заявки (код = приглашение репетитора) |

Тип класса репетитор выбирает при создании и может поменять. Класс можно скрыть из каталога совсем («только по коду») — так работают сегодняшние группы.

### 3.2. Кто может вступить

- **Ученики** и **репетиторы** — да.
- **Родители** — нет: у них отдельный режим (раздел 6).
- **Ученики младше порога возраста** — только с согласия родителя (раздел 7).

### 3.3. Роли внутри класса

| Роль | Права |
|---|---|
| Владелец (репетитор, создавший класс) | всё: настройки, ДЗ, оценки, посещаемость, оплата, модерация |
| Участник-ученик | ДЗ, свои оценки и посещаемость, лента (чтение), чат |
| Участник-репетитор | лента (чтение), чат; без доступа к оценкам, оплате и телефонам учеников |

Соведущий репетитор (несколько ведущих в классе) — позже, если попросят.

### 3.4. Что видит посетитель до вступления

- название, предмет, уровень, описание, открытый или закрытый;
- репетитор: имя, фото, предметы, короткое «о себе»;
- **лента** класса (объявления);
- число участников — да, **список участников — нет**;
- **чат — нет** (только участники).

## 4. Каталог

### 4.1. Поиск

Поиск по **предмету**, внутри предмета — по **уровню**. Дальше — по языку обучения, формату (онлайн / офлайн) и городу, если окажется нужно.

Предметы и уровни — **фиксированный справочник**, который мы ведём на сервере (не свободный текст, иначе поиск не работает). Справочник расширяется без релиза приложения.

Начальный справочник (уточнить с первыми репетиторами):

| Предмет | Уровни |
|---|---|
| Английский | A1, A2, B1, B2, C1, C2; IELTS, CEFR-экзамен |
| Русский язык | начальный, средний, продвинутый |
| Узбекский язык | начальный, средний, продвинутый |
| Математика | 1–4, 5–9, 10–11 класс; подготовка к экзаменам (DTM/абитуриент) |
| Физика, химия, биология | 7–9, 10–11 класс; абитуриент |
| Программирование | начальный, средний |

### 4.2. Порядок выдачи

Сначала простое: свежие и активные классы выше. Платное продвижение — позже (раздел 9).

## 5. Общение в классе

В классе два канала:

| | Лента | Чат |
|---|---|---|
| Для чего | объявления репетитора | разговор участников |
| Кто пишет | репетитор | все участники (репетитор может закрыть чат на запись) |
| Хранение | постоянно | **удаляется автоматически** |
| Видят посетители | да | нет |

### 5.1. Чат

- **Автоудаление через 24 часа** по умолчанию. Репетитор может выбрать меньше: 1, 6 или 12 часов.
- **Хранение дольше 24 часов — платно** (7 дней, 30 дней, без удаления) — этап 3.
- Ценность для учеников: общение о предмете, speaking-клубы, поиск единомышленников, общение со сверстниками.
- **Личных сообщений нет.** Общение только в классе, репетитор видит всё.
- Первая версия — **текст**. Фото и голосовые — позже (через модуль файлов, тоже с автоудалением).
- «Удобно как мессенджер»: сообщения приходят сразу, есть push, чат открывается мгновенно.

### 5.2. Модерация

**Репетитор в своём классе:**
- удаляет любое сообщение;
- запрещает участнику писать (только чтение);
- удаляет участника из класса;
- блокирует (участник не сможет вступить снова);
- закрывает чат на запись для всех (класс становится «каналом»).

**Жалоба на платформу** — у каждого сообщения и участника, в том числе на самого репетитора. Жалоба уходит нам.
- Сообщение, на которое пожаловались, **сохраняется до разбора жалобы**, даже если его время истекло. Остальные сообщения удаляются по таймеру.
- Разбирает владелец продукта (на старте вручную). Действия: удалить сообщение, заблокировать пользователя, скрыть класс из каталога, удалить класс.
- Это требование Google Play к приложениям с пользовательским контентом. Ещё нужны «Условия использования» с запретом недопустимого контента (раздел 8).

### 5.3. Как мы описываем ценность

Наружу (описание в сторе, реклама): общение по предмету, speaking-клубы, единомышленники, общение со сверстниками. Не используем формулировки, которые звучат как приглашение к обсуждению людей («сплетни») — это риск травли и вопросы от Google и родителей.

## 6. Режим родителя

Родитель **не вступает** в классы. У него своё:

1. **Результаты детей:** классы ребёнка, оценки, посещаемость, ДЗ (есть сегодня).
2. **Согласия:** подтверждает вступление ребёнка в открытые классы (раздел 7).
3. **Каталог как маркетплейс обучения:** находит и изучает репетиторов и учебные центры: профиль, предметы, классы, отзывы (позже). Записывает ребёнка — через заявку в класс от имени ребёнка или контакт с репетитором (уточнить на этапе 3).

---

## 7. Дети и согласие родителя

- При регистрации ученик указывает **год рождения**.
- **Порог возраста** — уточнить у юриста (13, 14 или 16 лет).
- Ученик **младше порога**:
  - вступает в **открытый** класс → родителю приходит запрос, родитель подтверждает;
  - родитель может включить в своих настройках «Разрешать вступать без моего подтверждения»;
  - **без привязанного родителя** в открытые классы не вступает;
  - в **закрытый** класс его подтверждает репетитор; родитель получает уведомление.
- Список участников класса посторонним не виден; телефоны учеников видит только владелец класса (сделано).

---

## 8. Правила, закон и данные

- **Google Play:** приложение с пользовательским контентом и детьми среди пользователей. Нужны жалобы и блокировка (раздел 5.2), «Условия использования», честная анкета Data safety, решение по целевой аудитории (Families или 13+) — с юристом.
- **Политика конфиденциальности** дополняется: чат, срок хранения 24 часа, жалобы, год рождения, каталог (что видно посторонним).
- **«Условия использования»** — новый документ: что запрещено, как модерируем, ответственность репетитора за класс.
- **Данные:** правила переноса данных остаются (docs/architecture.md): постоянные данные в Postgres и S3, push без имён и текста сообщений («Новое сообщение в классе English B1»), Sentry без персональных данных. Автоудаление чата уменьшает объём хранимых данных детей.
- **Модерация — ежедневная работа.** Жалобы нужно разбирать быстро; это обязательство владельца продукта.

## 9. Заработок (порядок проверки)

1. **Ядро бесплатно** — чтобы репетиторы пришли.
2. **Хранение чата дольше 24 часов** — платно для класса.
3. **Продвижение класса в каталоге.**
4. **Профили учебных центров.**
5. **ИИ-функции** — после теста, под подтверждённые боли (release-strategy).

Цены и способ оплаты (Click, Payme, Google Play Billing) — решить к этапу 3. Важно: оплата цифровых функций внутри приложения на Android по правилам Google обычно идёт через Google Play Billing — уточнить до запуска платных функций.

---

## 10. Что мы НЕ делаем

- Не называемся мессенджером.
- Нет личных сообщений.
- Нет публичных профилей учеников и общей ленты «для всех».
- Нет звонков, видео, историй.
- Чат не хранится вечно бесплатно.
- Не бросаем ядро: ДЗ, оценки, посещаемость, оплата — остаются и развиваются.

## 11. Этапы

| Этап | Что | Что проверяем на тесте |
|---|---|---|
| **1. Чат в классе** | чат с автоудалением (24 ч и меньше), доставка сразу + push, модерация репетитором, жалоба на платформу с сохранением сообщения, «Условия использования» | общаются ли ученики, возвращаются ли каждый день |
| **2. Классы, которые можно найти** | открытый/закрытый класс, заявки и подтверждение, справочник предметов и уровней, каталог с поиском, превью класса для посетителя, вступление репетиторов, год рождения и согласие родителя | приходят ли в класс новые люди сами |
| **3. Маркетплейс и деньги** | профиль репетитора, режим родителя как маркетплейс, учебные центры, платное хранение чата, продвижение | после теста, когда в каталоге есть классы |

Этапы 1 и 2 — **до внутреннего тестирования** (тест должен проверять новую ценность). Этап 3 — во время закрытого теста и после. Новые части включаются флагами фич (`chat`, `catalog`) — можно включить сначала тестировщикам.

Перед этапами 1–2 — доделки из прошлого плана: спрятать «Риски» и «ROI», редактирование имени, кнопка вложений в ленте.

### Метрики теста

- **Чат:** доля учеников, написавших хотя бы раз за неделю; сообщений на класс в день; возвращение учеников на 7-й день.
- **Каталог:** сколько классов открытые; сколько заявок и вступлений без кода; время подтверждения заявки репетитором и родителем.
- **Ядро:** отмечает ли репетитор посещаемость на большинстве занятий; открывают ли родители результаты.
- **Безопасность:** число жалоб, время их разбора.

## 12. Что меняется в архитектуре (обзор)

Всё встаёт новыми модулями и миграциями по рецепту «Расширение без переписывания» (docs/architecture.md):

| Часть | Изменение |
|---|---|
| Классы (`groups`) | видимость (открытый / закрытый / только по коду), предмет и уровень из справочника, настройки чата |
| Участники (`group_members`) | участник — любой пользователь (ученик или репетитор), роль в классе, блокировки, запрет писать |
| Заявки | новая таблица заявок на вступление (ожидает / принята / отклонена), запросы согласия родителя |
| Справочник | таблицы предметов и уровней на сервере |
| Чат | новый модуль `chat`: сообщения со сроком жизни, фоновое удаление, WebSocket + Redis для доставки сразу, push |
| Жалобы | новый модуль `moderation`: жалобы, снимок сообщения, действия владельца продукта; простая страница разбора на сервере |
| Пользователь | год рождения ученика; настройка родителя «разрешать без подтверждения» |
| События | вводим внутренний издатель событий: заявка → уведомление репетитору, вступление ребёнка → запрос родителю, сообщение → push |
| Приложение | вкладки по ролям: «Классы», «Каталог»; у родителя — «Дети» и «Каталог» |
