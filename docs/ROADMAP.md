# Траектория развития MaMu Learn

> **Версия:** 1.0 — 3 октября 2026. **Владелец:** Murodjon.
> **Источники:** продуктовый бриф «StudyIn — продуктовый бриф, архитектура и
> дорожная карта» v1.0 (3 октября 2026) + фактическое состояние репозитория
> на 3 октября 2026 + `docs/research/01-jtbd-tutors.md`.
>
> Бриф отвечает на вопрос **«что и зачем»**. Этот документ отвечает на вопрос
> **«в каком порядке и по каким критериям двигаться отсюда»**. Если документы
> расходятся, решения брифа с пометкой [РЕШЕНО] главнее; статус берётся
> из этого документа, т.к. он сверен с кодом.

---

## 1. Полярная звезда

> **Учитель работает оператором Telegram, а не педагогом.
> MaMu Learn возвращает ему роль педагога: забирает хаос из Telegram-чатов
> и превращает его в порядок со статусами.**

Главная работа (JTBD №1) — **упорядочить хаос, который живёт в Telegram**.
Каждая фича, этап и приоритет проверяется одним вопросом:

**«Это уменьшает хаос из Telegram для учителя, ученика или родителя?»**

Цель MVP по брифу: закрыть полный цикл
**задание → выполнение → результат → уведомление родителя** без Telegram.

Траектория рынка: **Узбекистан** (валидация) → **СНГ** → **Азия и другие регионы**,
где репетиторы работают через мессенджеры.

---

## 2. Принципы траектории

1. **Ядро раньше расширений.** Пока цикл «задание → результат → родитель»
   не работает у реальных учителей, новые направления не начинаются.
2. **Валидация раньше масштаба.** Бета с 10 реальными учителями важнее
   любой следующей фичи (Lean-подход брифа, Фаза 2).
3. **Данные для метрик — с первого дня.** Схема БД должна поддерживать будущие
   метрики прогресса (ROI Dashboard, churn, Academic Twin). Ретроспективно
   данные не восстановить.
4. **Каждая фича закрывает реальную боль со скриншотов** Telegram-чата.
   Нет боли — нет фичи.
5. **Решённое не пересматриваем без новой информации** (журнал решений D1–D9
   в брифе, `DECISIONS.md`).

### 3.3. Сделано сверх плана MVP

Бриф [РЕШЕНО] выносит AI-функции и геймификацию за рамки MVP (v2–v3+), а роль
владельца центра — во v2. В коде уже есть AI-слой, геймификация, Owner Risk.

**Позиция:** построенное не удаляем, но **замораживаем развитие AI** до прохождения
беты (раздел 4, этап B). AI не закрывает главную работу «порядок из Telegram»
напрямую, и поддерживать его стоит дорого (OpenAI, сложность кода — см.
`backend-architecture-methodology.md`, P7).

### 3.4. Технический долг, найденный при запуске

Подробно — `docs/backend-architecture-methodology.md`, раздел 2. Кратко: `SELECT *`
ломает запросы при новых колонках, ошибки 500 не логируются, нет транзакций в
многошаговых операциях, нет интеграционных тестов против БД.

## 4. Траектория по этапам

```
 A. Довести MVP     B. Бета: 10        C. v2: центры       D. v3+: интеллект
    до релиза   →      учителей    →      и веб         →     и масштаб
 ─────────────────────────────────────────────────────────────────────────
 закрыть G1–G9      валидация JTBD,    роль владельца,    churn predictor,
 + «защита» бэкенда цены, метрики      Center, ROI UI,    AI-проверка ДЗ,
                    успеха MVP         веб, оплаты*       выход в СНГ/Азию
```

Переход на следующий этап — **только по критериям выхода** (ворота), а не по дате.

### Этап A — Довести MVP до релизного состояния

**Цель:** закрыть цикл «задание → выполнение → результат → уведомление
родителя» на телефонах учителей Узбекистана.

| Работа | Закрывает |
|---|---|
| Создать Android- и iOS-проекты Flutter, сборка в CI | G1 |
| Push родителю при пропуске и при новой оценке | G2 |
| Перевести экраны на `AppLocalizations`: русский и английский | G3 |
| Привести SMS-правила к брифу (5/час, 5 мин, 5 попыток) | G4 |
| PDF-вьюер, CSV-экспорт журнала | G6, G7 |
| Теги тем у заданий | G8 |
| «Защита» бэкенда: явные колонки, логирование 5xx, интеграционные тесты, транзакции | Тех. долг |

**Ворота A → B:** приложение ставится на Android-телефон; учитель проходит
сценарий «создать группу → выдать ДЗ → проверить → родитель получил push»
на русском и на английском без помощи разработчика; crash-free ≥ 99,5 % на внутреннем тесте.

### Этап B — Бета с 10 учителями (валидация)

**Цель:** проверить главную гипотезу брифа — *«учитель перейдёт с Telegram,
если ценность видна за 10 минут»*.

| Работа | Зачем |
|---|---|
| Найти 10 учителей (в т.ч. из того самого Telegram-чата) | Бриф, шаг 6 |
| 12–15 switch-интервью по `research/01-jtbd-tutors.md` | Подтвердить JTBD и приоритеты |
| Интервью с 5+ владельцами центров о метриках прогресса | Закрыть Q2, основа ROI Dashboard |
| Минимальная продуктовая аналитика (события) | Считать метрики успеха |
| Проверить готовность платить $5 / $25 | Закрыть Q5 |
| Юзабилити-тесты по `research/02-ux-evaluation-methodology.md` | Качество ключевых сценариев |

**Ворота B → C (метрики успеха MVP из брифа):**

| Метрика | Цель |
|---|---|
| Активация (создал первое ДЗ) | > 60 % |
| Time to first assignment | < 10 минут |
| Retention D7 / D30 | > 40 % / > 25 % |
| Active / Registered | > 60 % |
| NPS | > 50 |
| API p95 | < 300 мс |
| Доставка push | > 95 % |

Плюс решение по **Q1** (кто первый клиент — репетитор или центр) на данных беты.

### Этап C — v2: центры, веб, монетизация

Содержимое зависит от ответа на Q1 и результатов беты. Кандидаты:

| Направление | Условие запуска |
|---|---|
| Роль владельца центра, тариф Center, `organization_id` в корневых сущностях | Q1 = «центр» или 3–5 центров готовы платить |
| Parent ROI Dashboard — полноценный UI | Метрики прогресса зафиксированы (Q2) |
| Веб-версия для учителя | Учителя в бете работают с компьютера |
| Тарифы Free / Pro / Center | Проверены в бете (Q5) |
| Учёт оплат учеников учителю (суммы, периоды, напоминания) | Интервью подтвердят O1–O2 из JTBD — **не путать** с подпиской MaMu Learn |
| Расписание занятий (`lessons`) | Боль «во сколько урок?» подтверждена |
| Геймификация / рейтинг группы | Проверить после ядра |
| Вход через Google / Apple | По запросу рынка |

### Этап D — v3+: интеллект и масштаб

| Направление | Условие |
|---|---|
| Churn Predictor для владельца | 3–6 месяцев истории данных |
| Academic Twin (профиль сильных и слабых тем) | Наращивается постепенно, с тегами тем из этапа A |
| AI-проверка ДЗ | Ядро стабильно, есть спрос; отдельный сервис через очередь |
| Выход в СНГ, затем Азию | Удержание в Узбекистане на целевых метриках |
| Видеоуроки (`meeting_url`) | Не приоритет |
| Learning GPS | Долгосрочно, нужны годы данных |
| Переезд хостинга в Узбекистан | Когда этого потребует закон о персональных данных (Q7) |

## 6. Не делаем без явного запроса

Решены или отложены владельцем, повторно не предлагаются:
Dart-бэкенд · Learning GPS · AI-проверка ДЗ · видеозвонки · микросервисы
(целевая форма — модульный монолит).

## 7. Как обновлять этот документ

- После каждого этапа обновлять раздел 3 **по факту в коде**, а не по плану.
- Закрытый вопрос из раздела 5 переносится в `DECISIONS.md` как решение.
- Новая идея попадает в этап C или D с условием запуска, а не в текущую работу.
