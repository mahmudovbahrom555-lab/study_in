# AI CONTEXT — StudyIn

> Вставляйте этот блок в начало нового чата с AI-ассистентом.
> Источник: продуктовый бриф v1.0 (раздел 12), обновлено по факту репозитория 2026-10-03.

**Проект:** StudyIn (ранее RepetApp) — мобильная платформа (Flutter + Go) для
репетиторов и учебных центров Узбекистана. Заменяет хаос Telegram-чатов: группы,
ДЗ, тесты, журнал, посещаемость, родительский модуль.

**Главная работа (JTBD №1):** упорядочить хаос, который живёт в Telegram.
Каждую фичу проверять вопросом: «Это уменьшает хаос из Telegram?»

**Роли:** учитель (платит), ученик, родитель (только чтение) — бесплатно.
Владелец центра — v2.

**Стек:** Flutter (Riverpod, go_router, Dio, Hive) · Go 1.25 (Chi, sqlx/pgx,
PostgreSQL 16 + pgvector, Redis 7, MinIO, Asynq, golang-jwt, viper) · Eskiz.uz · Hetzner.

**Неизменные правила архитектуры:** Clean Architecture (домен без инфраструктуры,
зависимости через интерфейсы); Feature-First → целевая форма модульный монолит
(`docs/backend-architecture-methodology.md`); UUID; soft delete (`deleted_at`);
JWT access 15 мин / refresh 30 дней с ротацией; nullable `organization_id`;
релиз на 2 языках — русский и английский (решение 2026-10-03, заменяет 4 локали брифа; узбекский отложен).

**Текущий этап:** A — довести MVP до релиза (`docs/ROADMAP.md`, раздел 3–4):
нет Android/iOS-проектов, нет push родителю о пропуске,
SMS-правила не по брифу. Затем B — бета с 10 учителями.

**AI-функции:** уже построены (сверх плана MVP), развитие заморожено до беты.

**Не предлагать без запроса:** Dart-бэкенд, Learning GPS, AI-проверку ДЗ,
видеозвонки, микросервисы — эти вопросы решены или отложены.

**При проектировании таблиц** всегда спрашивай: поддержит ли схема будущие
метрики прогресса (ROI Dashboard, churn, Academic Twin)?

**Стиль общения:** прямое мнение сразу, честная оценка; дополнительные идеи —
как варианты на будущее, а не немедленная реализация; не писать код, пока не
попросят; отвечать на русском.

**Документы:** `docs/ROADMAP.md` (траектория) · `DECISIONS.md` (решения) ·
`docs/research/` (JTBD, методология UX) · `docs/backend-architecture-methodology.md`.
